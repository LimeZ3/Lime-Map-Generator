The separate joint source-layer pilot now has a catalogued experimental branch: 13 simultaneous source channels plus 12 rating controls, 782 train / 69 validation maps. This pilot does not replace the selected stages below; its actual receipt and raw galleries are linked from the branch.

Open index.html directly in a browser. No server, GPU inference, training, installation or online deployment is needed. pipeline-overview.png is the standalone generation chart.

Default source previews use Setons Clutch – FAF version 8553_17709; original model results and training-map figures remain behind disclosures with their actual provenance. The atlas also contains model contracts, a searchable document library and work status. Existing #overview links still open the generation chain. The folder remains model-atlas to preserve local links. project.js owns the project sections; library-data.js is the curated document index (titles, categories and relative paths). Update these when adding project entry points. The atlas is a saved reference, not live job monitoring.

The atlas separates current models, their deterministic tooling, planned stages and checkpoint-bearing historical runs. Inputs at generation, outputs and training targets are distinct. Images come from real saved arrays except the explicitly labeled Gaussian-noise illustration. PNGs visualize numeric channels; they do not imply that map previews were the training inputs.

Each selected model includes an actual training receipt: checkpoint-pinned dataset release, train/validation counts, exact source archive, array shapes/dtypes, target-channel PNGs, source-condition PNGs, scalar profiles and loss-mask semantics. The shared Argon FAF example belongs to the train split of all four releases. It is shown before random augmentation; resource-loader cache quantization is noted.

Controls & data use (index.html#controls) distinguishes learned conditioning, diffusion sampling, decoding, composition and export settings. It shows train-only control support, the saved seed-303 request, and available-but-unused air/drop masks and automated gameplay ratings. These are not community votes.

Tensors & map data (index.html#training) inventories physical layers and derived gameplay observations together. Rating coverage is read from source metadata for the exact curated marker cohort, with scenario identity and hashes checked. It lists native spatial arrays and structured front/economy/naval records, not just neural input/target arrays. Economic safety and independent army-passage count are not claimed as established automatic measurements. The linked V2 gameplay-conditioning proposal is explicitly design-only; no selected model was changed.

Updating

catalog.json is the curated source of truth for purposes, tensor contracts, selected checkpoints and human-reviewed status. For every new stage or changed selection, record:

  • Input shapes, meanings and origin, including controls/noise where applicable.
  • Output shapes/semantics and what the network does not produce.
  • Separate source dataset and training-target representation.
  • Actual loader-consumed arrays/profile origin, target vs condition vs loss mask.
  • Update controls.json for learned controls and non-neural settings, keeping extracted-but-unused data and historical conditioning separate from active use.
  • Selected checkpoint and exact step, training state and player/playtest state.
  • The subsequent decoder/composer/validator, including bypassed constraints.
  • Actual example channels/results, with source vs generated labels.

Then refresh from saved artifacts:

$env:PYTHONPATH = 'src'
$env:OPENBLAS_NUM_THREADS = '1'
$env:OMP_NUM_THREADS = '1'
.venv/Scripts/python.exe -m supmapai.tools.build_model_atlas

The builder creates generated/atlas-data.js, JSON provenance and channel PNGs. It scans checkpoint directories and inspects trusted local checkpoint metadata with map_location='meta', mmap=True; no full-weight GPU load or model execution is performed. It refuses stale selected checkpoint steps and missing references. New historical runs are automatically listed; they are not automatically promoted to the active generation chain. A new role also needs an explicit chart branch. Early experimental contracts are separate from modern encodings; do not relabel an old water-mask model as signed-distance prediction.

Browser verification and PNG refresh:

$env:PLAYWRIGHT_PACKAGE = '<absolute path to installed playwright package>'
node tools/check_model_atlas.mjs

The test uses an isolated temporary headless Edge profile, opens the offline page, checks all model/tool views at desktop/mobile widths, validates image loading and basic interactions, and captures pipeline-overview.png. Browser screenshots remain under .tmp/model-atlas-browser. This does not inspect or change the user's existing browser tabs.

vendor/lucide.min.js and its license are copied from the installed Lucide package for offline icons. There are no runtime CDN calls or analytics.

Snapshot Boundaries

The main visible sample is generated seed-303 terrain with water request 20%. The extraction/target example is Argon FAF (11802_23428), intentionally a different map; source targets are not secretly inputs for the generated sample. Texture images are extracted source data, not learned outputs.

Four trained stages are selected. Natural reclaim was visually preferred and seen in game; its 21-minute run remains paused. Wreck learning finished a five-minute pilot and exported a runtime script, but is not yet playtested. Texture extraction completed on 1,117 maps with validity caveats; there is no trained texture model. Living civilian and spawn-layout stages are not trained.

Historical checkpoint facts are a reference inventory, not a claim that every old run is compatible with current data or part of the generation chain. Training loss, source agreement, file integrity and gameplay quality remain different kinds of evidence. Refresh status after future player reviews or runs.

Entity-overlay backgrounds and section review

Starts, markers, props/wrecks, civilians and analytical overlays default to a separate official FAF vault image with adjustable brightness (default 10%), labeled as context only. The Background brightness slider at 0 hides context; full-resolution PNG links contain only the transparent layer. Do not use extracted terrain as an implicit background. Context never changes source tensor values, and vault registration uncertainty stays visible.

See layer-review.md for the 25 October section review, exact saved artifact coverage and pending TODOs. The former atlas air-distance proxy and duplicate abundance aggregate have been removed from the displayed section. Prefer existing artifacts; record missing exact-version outputs instead of substituting stock variants or recomputing without a request.

Global display controls and side-specific fields

Two 0–100 sliders stay at the bottom of the desktop left sidebar: Background brightness defaults to 10, and Mask opacity defaults to 100. Settings apply across atlas routes and survive reloads through local browser storage when available. Background 0 hides only the separate vault image; mask 0 hides data previews. Sliders remain available under navigation on mobile.

Layer PNGs have full base opacity; their display alpha is controlled globally, including model tensor galleries. This supersedes the previous fixed 50% rule. Source tensors and numeric values never change. Original vault reference cards are not masks and retain their normal appearance.

Side-specific air fields show both archived sides, blue and orange with violet overlap. Slots are never silently renamed. The known DualGap ARMY_1/ARMY_12 air pair issue is visibly flagged; newer frontier paths use ARMY_1/ARMY_2. Saved mirrored frontier branches are displayed for both sides.

The maps extraction work queue tracks pair correction, hover/navy battle paths, resource-zone quality/coverage and contestability semantics. Atlas presentation changes do not claim to fix scientific outputs.

All comparison rows now share that separate vault context, including terrain, water and surface appearance. Reducing albedo opacity reveals the context rather than merely dimming the image over an empty background.
