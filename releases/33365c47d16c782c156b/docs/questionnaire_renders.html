Integration files

  • manifest.json: completed assets, relative paths, dimensions, checksums, map/version identity, visibility, default configuration and uncertainty.
  • maps/<map_id>_<version_id>/asset.json: per-map asset metadata/checkpoint.
  • maps/<map_id>_<version_id>/provenance.json: source hashes and validation.
  • questionnaire_assets.json: exact-version joins to questionnaire entry IDs.
  • render_catalog.csv: coverage of every catalog entry, including unavailable maps.
  • failures.json: failed render names, identities and reasons. Failures are not automatically retried on resume with the same pipeline/source fingerprint.

The existing 6,177-entry Netlify questionnaire has 6,131 exact folder matches in the available latest-version library. Identity checks also require any explicit vault map/version IDs to agree. Missing or older questionnaire versions remain visibly unmatched. Do not join by display name or replace them with latest-version images under an older review identity.

An asset host should expose the maps directory and manifests under a chosen base URL. Resolve relative paths against that URL. Use web images for the main view and native images for enlargement. Use adaptive_link_view_available before exposing the adaptive-link view; unsupported scripts do not have guessed links. Static resource views show all definitions, while supported adaptive views show default activation. Show reclaim as a known baseline when unknown entities exist, and preserve static-pathing qualification. Local asset generation does not deploy or change the questionnaire website.

Run and monitoring

powershell -NoProfile -ExecutionPolicy Bypass -File scripts/Start-FAF-Renders.ps1

Double-click scripts/Watch-FAF-Renders.cmd for a live status display, or run:

powershell -NoProfile -ExecutionPolicy Bypass -File scripts/faf-render-status.ps1

Two workers render concurrently. The parent records a heartbeat every five seconds and refreshes manifests every minute and at completion. Each map has a 240-second deadline; a timeout or crashed worker is recorded and the batch proceeds. Completed per-map checkpoints survive interruption and are included in the next resume. A fingerprint includes the renderer/extractor code and pinned source archive. Keep the computer awake for the run.

Large tensors and entity inventories are not kept in this web-assets batch; the raw map library remains available for separate training extraction.

Checkpoint replacement retries bounded temporary Windows file-lock failures. The prior valid JSON remains readable until replacement succeeds. Resume fingerprints now distinguish extraction/asset-format changes from operational checkpoint fixes, so this fix reuses the existing render collection and failure list. Compatibility with the prior fingerprint is restricted to the exact matching extraction and packaging implementations. Intermediate per-map files are removed after packaging. Native and web PNGs consume additional disk space. The run stops below 10 GiB free space.

Unknown values stay flagged.
