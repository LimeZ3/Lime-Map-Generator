Heatmap Reclaim Composer V1

Responsibility

The selected neural model supplies two allocation fields: tree energy and natural-rock mass. The composer turns those fields into actual .scmap prop instances. It does not invent forest/rock regions, retrain the model, choose spawn locations, relocate resources or change terrain.

Input for this first export is the user-preferred EMA prediction at update 20,657 on the generated 10km seed-303 terrain. Terrain, learned mex/hydro positions, conditioning fields and checkpoint hashes are checked against the review artifacts before composition. Training remains paused.

Algorithm

  1. Normalize the two nonnegative allocation fields without thresholds or sharpening. Apply the existing 180-degree average symmetry projection.
  2. Divide each role's chosen physical budget across an 8x8 grid of budget areas using the sum of the fine allocation field. Each area is 64 world units wide. This coarse grid is a value-accounting boundary, not a replacement heatmap.
  3. Each area has a seeded asset/position candidate stream. Choose assets from a predefined coherent stock pool, then sample positions from the original 128-grid probabilities inside that area. There is no uniform fallback.
  4. Place matching 180-degree pairs, including asset, scale and paired yaw. Ground Y by bilinear sampling of the unchanged native terrain. Quantize XY inside the selected fine cell so rounding cannot escape learned support.
  5. Stop an area before its next complete prop pair would exceed its local budget. Leave the residual there and report it. Do not compensate in a different area or change the last asset to squeeze in a smaller one.

Energy/mass values come from installed stock blueprints with active FAF economy overrides and merge handling. Five tree variants (birch, oak and pine variants) and seven rock/rock-pile variants are supported in this initial evergreen pool. Asset choice is procedural, not learned. Instance scale is one; blueprint UniformScale remains the game's responsibility, avoiding double scaling. Tree-group blueprints, wrecks and living civilian units are not emitted yet.

The tree budget means tree energy, the rock budget means rock mass. Tree mass is reported independently and included in total reclaim mass. Any cross-resource yields are counted; do not interpret rock mass as total mass. Stock and FAF economies differ, so these budget values target the active FAF blueprints used by the existing offline FAF executable, not vanilla balance.

Optional Constraints

Default minimum spacing is zero to expose the raw learned allocation. No dry land, slope, cliff, shoreline, buildability, spawn clearance or resource-marker mask is applied. Underwater props remain possible. Mexes, hydros and spawns remain at their original coordinates, without flattening or snapping.

--min-spacing optionally enforces center spacing within each role, not between trees and rocks. Failed attempts stop that area's stream and leave a local shortfall. This is not a mesh-footprint collision solver. A global entity cap (20,000 by default) bounds runtime and output size; cap shortfalls are reported.

With default spacing and an inactive cap, increasing budgets preserves existing asset/XY/yaw selections and adds more. This set-inclusion property is verified for low -> medium -> high. Optional spacing can couple neighboring areas, so that strict nesting guarantee does not apply with spacing enabled.

Windows Commands

$env:PYTHONPATH = 'src'
$env:OPENBLAS_NUM_THREADS = '1'
$env:OMP_NUM_THREADS = '1'
.venv-codex/Scripts/python.exe -m supmapai.export.compose_reclaim_maps --out data/exports/heatmap_reclaim_composer_v1

For another trial choose a new output directory. Controls include --presets low medium high, --budget-scale, --seed, --tiles, --min-spacing, --max-props, --review, --condition, --resources and --template. The test driver uses the frozen seed-303 conditioning/resource example; the core compose(fields, [tree_energy, rock_mass], vertices, assets, ...) API accepts independent physical budgets. No GPU inference or training is required here.

The gallery contains high-contrast actual point placements, enlarged base crops and the unchanged learned allocation fields. Each export contains scenario, save, script, preview, native map and composition metadata. The manifest is compatible with scripts/Install-SymmetryMaps.ps1; this command does not install or launch maps. Textures remain the existing inherited base material.

*_composition_fields.npz stores projected allocation, desired physical-value grids and actual composed physical-value grids. Budget JSON includes requested, achieved and unmet values by area, asset counts and stopping reasons. Source and blueprint provenance is recorded; raw datasets and model files are untouched.

Native readback verifies every exported prop's asset and position and confirms unchanged heights. Unit tests cover value budgets, incidental tree mass, exact symmetry, zero support, underwater retention, seeded nesting, spacing failures, the safety cap and native serialization. In-game appearance and runtime reclaim behavior still require a playtest; they are not certified by file readback.

Wreck-mass learning and runtime composition are implemented as a separate pilot in wreck_reclaim.md, preserving this approved native tree/rock composition.
