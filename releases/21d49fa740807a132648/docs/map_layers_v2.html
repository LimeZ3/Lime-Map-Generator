Map layers V2: implementation progress

Water decoding correction (2.0.1): water elevation and enabled state now come from the serialized SCMAP water block for versions 56 and later. Histogram inference and texture-offset guesses are no longer used. Unsupported or invalid water blocks are reported as unresolved. Regenerate earlier V2 previews/tensors before using them. Canis smoke export changed from guessed elevation 53.4918 to serialized elevation 36, with 11.7973% of full-map cells below that surface. This is a file-derived mask, not a claim of in-game validation or agreement with a potentially custom vault image. Use --fetch-vault-previews to cache each map's official vault image and produce comparison.png (vault, terrain/water, pathing, markers). Without the flag, cached images are reused and no network request is made.

Implemented first milestone:

  • Shared terrain_layers.calculate for extraction, training tensors and V2 exports.
  • Ground and amphibious slope limit 0.75; amphibious depth limit 25.
  • Seabed slope included; no T1/T2 navy classifications. These remain static estimates, not engine-verified footprint clearance or dynamic pathfinding.
  • Separate native height vertices, cell heights, depth and movement arrays with world coordinates (array[z,x]). Full-map data retained; playable bounds recorded.
  • Native combined terrain/water, pathing and numbered marker PNGs for detailed inspection.
  • Source hashes, map/version IDs, extraction schema and per-layer uncertainty in record.json.
  • Prop and statically identified reclaim entities with distinct instance IDs and blueprint references. Reclaim rasterizer sums known mass/energy, preserves stacked instance counts, and reports unknown values and out-of-bounds objects separately.
  • Script-option detection is preliminary evidence only. Adaptive links are explicitly unresolved. Spawn slot numbers follow ARMY_1 through ARMY_16 rather than geometric order.

Run a small local validation pass:

$env:PYTHONPATH='src'
.venv-codex/Scripts/python.exe -m supmapai.tools.extract_layers_v2 --catalog data/raw/faf_maps/latest_20261008/map_catalog.csv --output data/processed/layers_v2_smoke --limit 5

Each map/version directory has record.json, layers.npz, terrain_water.png, pathing.png, markers.json, markers.png, entities.json, and reclaim.npz. The report records extraction errors without stopping other maps. Failed/skipped downloads are not selected. There are no network calls or executions of map scripts.

V2 retains raw water masks; legacy terrain metrics can include explicitly reported cleanup of uncertain water. Do not compare raw full-map arrays with cleaned playable crop statistics without applying their recorded policy and bounds. Unknown water has a false movement-validity mask; zero depth is then a placeholder, not evidence of dry terrain. Inferred water level carries its original source/warning.

Training exports append amphibious_passable_mask as a 13th channel and include schema/movement provenance in metadata_json. Existing tensor archives are untouched. New archives require models configured for their listed channels; 12-channel checkpoints must not be loaded against the new schema without an explicit channel selection or migration. Legacy corner-cleaned water masks require regeneration before training export; uncertain small-component cleanup is reconstructed using the recorded policy.

Remaining milestones:

  1. Validate runtime blueprint defaults/modifications and wreck values. Static blueprint lookup now records source archive/member hashes and numeric baseline values. Empty or expression-valued fields remain unknown. Known-value grids must be accompanied by unresolved counts; they are not complete reclaim totals.
  2. Extract adaptive options, activation rules and resource-to-spawn relationships from supported script patterns; resolve configured variants and active slots.
  3. Add synchronized interactive zoom, profile selection and adaptive controls to the annotation application. PNGs are preliminary inspection outputs.
  4. Validate engine movement and runtime reclaim/resources on a selected reference set, then run the library-wide extraction and define family-aware dataset splits.

Tests cover slope/depth boundaries, underwater cliffs, cell spacing, tensor agreement, stacked reclaim conservation, unknown values, and map bounds.

Reclaim/placed-entity milestone (2.1.0): use --game-data with the installed game gamedata directory, optionally --faf-archive with a local FAF archive. The output blueprint_index.json records the baseline source, not proof of current FAF runtime equivalence. Explicit blueprint replacement and Merge = true are distinguished; Lua blueprint hooks are not executed. Map Lua is never executed either.

Every static SCMAP prop and save-file prop/unit is preserved in entities.json and entities.csv, including coordinates, blueprint ID, group/army and value provenance. Live units/buildings do not contribute their construction cost to ground reclaim. Potential wreck mass/energy is separate. Units inside an explicit WRECKAGE group are classified as wreckage with their source unit ID; their runtime amounts remain unknown. Generic default-wreck props also remain unknown without that association. Script-created or conditionally removed entities are not resolved by this milestone.

reclaim.npz retains individual-cell values and counts. reclaim_mass.png and reclaim_energy.png show sums in 8x8-world-unit tiles with a fixed logarithmic scale (10,000 per tile saturates). Stacking adds values rather than overwriting instances. props_units.png distinguishes civilians, other units, explicit wreck groups and unresolved props. entities_comparison.png includes a cached official vault preview when available. Resource colours and icons come from the installed game's textures.scd; converted icons are local derived assets under ui_assets, not repository assets.

Runtime validation is still required for natural reclaim modifiers, blueprint hooks, health/overkill/water-dependent wreck amounts, civilian lobby options and scripted entity creation. Do not treat the baseline amounts as certified training targets yet.

Wreck-value milestone (2.2.0): a recognized local FAF Unit.lua rule is recorded with its SHA-256 in wreck_value_profile.json. For explicit WRECKAGE groups, calculate construction cost times wreck resource multiplier, halved for inferred Water-layer naval wrecks. Assume standard initialization with zero overkill and fully completed units. Air units use an inferred Air layer. Underwater units that are neither naval nor air retain unknown amounts because their movement layer is ambiguous. Unsupported local Lua rules also retain unknown amounts. This profile is not the current FAF develop formula: that source applies technology-tier and different submerged reductions. Do not mix these profiles in training without version labels/runtime validation.

Calculated wrecks now contribute to reclaim grids. Each instance remains a separate record with source-unit ID, orientation, dimensions/scale and available blueprint appearance references. CSV includes these fields too; density totals never replace entity records. Missing numeric fields remain null, whereas numeric zero is known.

Updated policy (2.3.0): empty or absent reclaim fields on a resolved prop blueprint default to zero, following the user's in-game validation. reclaim_field_status retains whether each value was numeric, empty, missing or an unparsed expression. Expressions we cannot evaluate, missing blueprints and ambiguous wreck layers still remain unknown. This supersedes the earlier empty-field policy.

Use --faf-source-archive to apply a pinned FAF source ZIP after base game data (and after --faf-archive if supplied). Seton's reference snapshot is FAF develop commit c7d9d129cc9085ddf84cc49aa3f13af91afd9509. It includes Unit.lua and all six source unit blueprints found in Seton's save file. Wreck mass uses blueprint mass cost * Wreckage.MassMult * tech-tier factor (T1 .9, T2 .8, T3 .7, experimental .6), then *.6 for Water/Sub/Seabed layers. Wreck energy uses cost * EnergyMult, then the submerged factor; it does not receive the mass tier factor. Assumptions and source hashes/commit remain recorded. A source snapshot on develop is not a declaration of the user's active live game balance version.

prop_type separates tree/rock/other; prop_type_source records the method. Tree and TreeGroup ScriptClass is preferred, then tree directory names. Rock classification uses rocks directories or rock/iceberg/crystal blueprint names and is therefore a heuristic. is_tree_group distinguishes a cluster blueprint from an individual tree. The renderer uses green trees, grey rocks, cyan other props, yellow wrecks, and red unresolved props. Entity identity and original appearance references remain unchanged.

Mass palette update (2.3.1): the mass view interpolates from faint desaturated green at 0 to brighter green at 100, yellow at 500 and red at 10,000 mass per 8x8 tile. Amounts strictly above 10,000 use dark red. Empty tiles retain the dimmed terrain background. The legend and record.json specify thresholds and aggregation units. Energy rendering and numerical reclaim arrays are unchanged.

Density resolution update (2.3.2): mass and energy previews sum into 4x4-world-unit tiles. Mass thresholds remain 0, 100, 500, 10,000 and dark red above 10,000 per tile. Numerical per-cell reclaim arrays and entity values remain unchanged.

Prop variety (2.4.0): unique_prop_blueprints counts distinct normalized blueprint paths across all static SCMAP and save-file props, including decorative props. Paths are case-insensitive, slash-normalized and stripped of the initial slash. Placed units and unit-source wrecks are excluded from this prop metric. Different tree-group/scale variants count as different blueprints; this is asset variety, not a proven measure of design effort or unique meshes. Missing IDs are counted separately. Tree/rock/other instance counts and unique blueprint counts accompany the total. map_metrics.csv is emitted per map and aggregated in the output root; prop_blueprint_counts.csv lists each unique blueprint and its instance count. The props preview also displays the primary unique count.

--reclaim-tile-size N configures both mass and energy density previews, default 4. Thresholds remain absolute sums per tile, so changing tile size changes the amount aggregated into each colour. Training arrays and entity values do not depend on it.

Adaptive wreck investigation (2.5.1): the verified Wrecks<n> helper pattern resolves conversion of saved units to wrecks based on active player count. Require the helper import/call, group selection, platoon creation and explicit zero-overkill wreck creation in source; group names alone are not evidence. --player-count selects the group; absent it, the static spawn count is an explicitly recorded assumption. Inactive groups remain in entity exports but not previews/density. Auxiliary map Lua files are now hashed too. Unsupported option-dependent wreck creation remains unresolved; no map Lua is executed.

The variety metric now includes active unit-derived wrecks, identified by original unit blueprint, along with static props. This supersedes the earlier exclusion of unit wrecks. unique_other_blueprints includes these non-tree/non-rock wreck identities. Additional fields separate static prop instances/varieties and wreck instances/varieties. Live units are still excluded from ground-prop variety.

Adaptive resource milestone (2.6.0): support the inspected CookieNoob/KeyBlue spwnMexArmy/spwnHydroArmy literal table pattern. CSV/JSON preserve declared slot membership and scaling-option thresholds rather than nearest-spawn guesses. --active-slot N selects active slots (repeat); absent it, all static spawn slots are explicitly assumed. --map-option key=value overrides numeric option keys. Lobby defaults are indices into the available values array, not necessarily keys. Commented-out options are excluded. --spawn-mex-slot N retains resources of a closed slot via the script's SpawnMex behaviour.

Supported initial resource rules: mirror pairs (1), used slots (2), require both pair members (3), fixed slot ranges (4-7), and cumulative tables referenced by the inspected FalseIfInList loop. A resource shared by multiple declared slots must satisfy every controlling slot because the script removes it if any owner is absent. Crazyrush-one-mex filtering is supported when its static list is present; runtime creation of additional mexes is not simulated. Unsupported scripts remain unresolved and do not receive guessed activation labels.

adaptive_options.json records option values, parsed lobby choices, associations, selected active slots, unsupported effect status and warnings. adaptive_resources.csv stores one row per resource definition with owner slots, option conditions and active flag. adaptive_slots.png draws coloured slot links, slot numbers, closed slots and red crosses on removed resources. The original markers view continues to show all definitions. Natural reclaim multiplier affects static prop values, with blueprint baseline retained. Tree regrowth is recorded but not simulated. Player-count wreck dependencies are recorded per entity and selected group. Such wrecks are globally controlled by player count; no spatial ownership is inferred.

Archsimkats reference: slots 1->Mass 23/25, 2->Mass 24/26, 3->Mass 31, 4->Mass 32. No slot-bound hydros. Four active slots yield 54 mexes, 6 hydros and 98 wrecks. Active slots 1/2 with dynamic_spawn=2 yield 52 mexes, 6 hydros and 34 wrecks. Optional civilian/wreck settings, faction-dependent choices, map expansion and arbitrary custom Lua remain separate unresolved effects.

Additional hydros and extra mexes have separate switches; mode 6 filters initial mexes through crazyrushOneMex. Runtime growth remains unenumerated.
