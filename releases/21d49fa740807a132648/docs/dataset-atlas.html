Dataset audit in the project atlas

The atlas Datasets → 1x1, 10km tab starts with the exact frozen collection of the local dataset reviewer: terrain_full256_controls_v3, 1,200 train and 110 validation maps. No held-out test set is included. Its membership comes from the published, hash-verified release, never from a newly inferred map filter. The collection identity is the SHA-256 of that release manifest. The reviewer's catalog and decisions must match it before a snapshot can be built.

This is the original audit population, including locally excluded maps. The current curated terrain membership is displayed separately and can be filtered. The original local exclusions initialize the shared dataset selection. All other maps default to Kept. Kept means included in the selection, not that a human has certified the map. Private local notes and undo history are not published. Atlas flags and notes remain separate review judgements.

Shared curation and manual symmetry

Sign in as the project owner to use each map's Kept checkbox and Manual symmetry suggestion selector. The controls appear in gallery cards, coverage table rows and map details. Decisions are stored in the Site's D1 database, shared across devices and publicly readable. A failed save remains visible; the control returns to its last saved state.

Keep page / Exclude page affect exactly the displayed page of up to 24 maps after filtering. Each request captures those exact map keys and versions. The server validates every key against the frozen cohort and applies one atomic SQLite operation: a conflict on any map changes none of the batch. Reloaded decisions allow the owner to review the state and retry explicitly.

Manual suggestions include named mirror axes, common rotational/radial orders, rotation-plus-mirror groups, asymmetric and unsure. Not suggested clears the human hint. Suggestions have a dedicated filter and remain independent of algorithmic symmetry classifications, scores and PNG overlays. They do not automatically change tensor masks or training labels; their usefulness can be evaluated later alongside the measured symmetry work.

The public /api/dataset-curation?format=selection endpoint returns the complete kept/excluded key lists, human symmetry suggestions, source-cohort fingerprint and decision versions for a future dataset build. The filtered inventory export also includes current shared decisions and suggestions. Existing frozen release memberships and checkpoints remain historical receipts; the next build should consume the explicit selection, preserve split/family rules and record a new release. Source maps and tensors are retained for audit and re-inclusion.

Views and evidence

The gallery can compare one selected source layer, derived tensor or training channel across maps. The coverage table, search, split/curation/membership filters and sorting work across the entire collection, with 24 maps per page. Open a map to toggle source, derived, training, ratings and question panels.

Previews are rendered from saved pinned arrays and entity records, not predicted data or new extraction. Native and Full256 target archive checksums are verified. Each tensor retains its array field, source artifact, original shape, dtype, finite check and numeric range. The display derivatives are 256px lossless WebP sheets; they are not raw tensor downloads or training data. Height contrast is map-relative, depth uses a 0–30-world-unit color scale, reclaim uses a log scale and per-map positive-cell contrast. Natural reclaim bins sum 2×2 world units. Sparse point/mask layers remain transparent over independently dimmable context.

Saved native physical channels are source-analysis representations. Their presence in this audit does not imply every selected generator consumes them. Supervised target channels are explicitly named; Controls & data use remains the authority for actual model inputs, targets, masks and composer settings.

The full-bright preview uses the FAF vault URL associated with the exact version. If unavailable, it falls back explicitly to the embedded author preview used by the local audit app. Neither is a fresh engine render or evidence of alignment. Saved source preview fallbacks and tensor previews are bundled in the snapshot.

Air masks preserve both actual selected slot names; no opposing mask is guessed by rotation. Native resource-area IDs are identified as resource grouping, not walking components. Only recognized saved route polylines can become battle-path previews; scalar front metrics never become invented paths. Hover/navy movement masks are not hover/navy battle-path predictions.

Ratings separate saved algorithmic 1–5 strategy labels (with confidence and availability masks), measured terrain/economy values and FAF vault community scores/review counts. None of those is competitive-quality certification.

Missing data, valid zero-valued layers, unsupported previews and exclusion from a role-specific release are distinct. Check the processed-release membership panel before treating an unavailable wreck-positive or other role target as a failed extraction. Adaptive script uncertainty and provisional resource zoning remain visible questions. Known work stays in map-extraction-todos.md.

Reproduce and maintain

$env:PYTHONPATH = 'src'
.venv/Scripts/python.exe -m supmapai.tools.build_atlas_datasets --workers 4
.venv/Scripts/python.exe tools/finalize_atlas_dataset_index.py

This reads existing artifacts, validates identities and renders audit previews. It does not train, download, re-extract, mutate curation decisions, change splits or approve maps. Run it after relevant recorded extraction/processing changes, then validate and follow atlas-publication.md to publish the GitHub snapshot.

The builder is src/supmapai/tools/build_atlas_datasets.py, the UI is docs/model-atlas/datasets.js, and generated content lives in docs/model-atlas/generated/datasets/1x1-10km. Stable per-map atlas review keys are dataset:1x1-10km:<map_key>. Dataset registration is recorded in docs/model-atlas/datasets.json.

Future large-map, naval, team-game, survival and co-op collections should get their own ID, explicit membership/scenario contract, split policy and source receipts. Do not append them to this frozen 1v1 collection or reuse its review keys when membership semantics change.

Extracted terrain symmetry layer

The derived-data panel now includes terrain-first symmetry from the pinned 1,310-map audit cohort. It shows family/order, axes, center, fit/domain errors, separate source-start/default-mex agreement, selected-pair checks and the saved 28-value condition. The panel refuses a mismatched cohort identity. Results are an extracted source-derived map-data feature with per-map review still in progress. Existing selected model inputs and membership are unchanged. See terrain_symmetry_detection.md. Regenerate/validate the small sidecar with tools/finalize_terrain_symmetry.py --run data/processed/terrain_symmetry_collection_v2 using PYTHONPATH=src; this does not rerender the collection or train a model.

The v2 presentation uses directional gradients rather than flat region colors. The pure gradient is available under each diagram, alongside its transparent PNG overlay. Rebuild it with tools/render_symmetry_assets.py using output data/processed/terrain_symmetry_assets_v2, after the detection finalizer; then run tools/audit_symmetry_assets.py. The categorical descriptor and source condition vector are unchanged by this rendering update.

Symmetry is registered as a normal Extracted source layers item (owner promotion, 26 October 2026). Its PNG is a direct external asset, so refreshing the lightweight dataset index registers it without rerendering sprite sheets. The index builder preserves sprite offsets and records source-derived provenance. Use Compare layer across maps: Symmetry, then the symmetry type, approximate or no-match filter.

Anchor-assisted layout update

The current extracted symmetry layer uses layout v2. Use the Symmetry filter for Approximate layout, Terrain only/layout unsupported, Recovered from height-only no-match, or remaining No match. The per-map panel separates earlier terrain evidence, full source starts/resources and the recorded default configuration. Asymmetric resources are allowed; rated status does not create a match.
