EXTRACT-05 Supporting slope tensor

Decision accepted; implementation pending. Calculate slope and include it

alongside terrain where relevant to models. Candidate field is physical

steepness 1 x 256 x 256, using physical cell spacing and validity neighborhoods.

Downstream models can derive it from their upstream terrain. Terrain slope

supervision can be calculated from predicted height; do not supply unavailable

clean target slope as an inference condition. Same-resolution target semantics,

loader/loss wiring and any loss weight still require validation. The selected

terrain model's encoded-gradient loss is not the proposed physical-slope loss.

Display-only additions are deferred; current checkpoints/outputs remain unchanged.

EXTRACT-06 Dataset release, non-square sizes and validity

Accepted scope; implementation pending.

  • 06a: introduce the non-square/unequal-side class. Preserve native/playable

    width and height, aspect ratio, bounds and padding masks. Do not squash a

    rectangular map into a square or silently add it to the 10x10 km cohort.

  • 06b: broaden from padding to auditing/solidifying the current 10x10 km

    1v1 dataset. Require name, stable ID, version, manifest and per-field readiness:

    sources, defaults, units/shapes, validity, extraction/semantic status, model use,

    unresolved data and required rebuilding. Starting candidate is the existing

    1,117-map curated cohort (1,020 train / 97 validation), not a new frozen release.

    Working name/ID are proposed in the plan; version is assigned at audit freeze.

    New audit finding: the 1,310-map parent inherited an earlier half-map filter,

    excluding 548 candidates. Review symmetry coverage and exclusion provenance

    before claiming a general 10km dataset; do not restore maps automatically.

EXTRACT-11 Settings-dependent entities and configured examples

Planned, linked to EXTRACT-14. Resolve which props, wrecks, civilians and

resource records activate or change quantity under defaults/options/active starts.

Later, supported low/medium/rich configurations may become separate extracted

examples and training conditions. They must have actual different tensors where

settings change data, not new labels on the same arrays. Generated adaptive maps

and version-enabled generated-map products are out of scope. Keep source author

version, dataset version and configuration variant IDs distinct. All variants

of a family remain in the same train/validation split.

EXTRACT-12 Special effects in map appearance

  • 12a — New tensor required; research and extraction pending. Locate effect

    IDs/asset-pool references, positions and available instance/default parameters

    such as scale, orientation and animation speed in map records/scripts. Do not

    assume all fields are serialized for every effect. Most maps may contain none;

    verified empty and unresolved extraction need different validity. Preserve

    instance identity and references separately from painted materials.

  • 12b — Defer representation discussion. Heatmaps are a candidate for later;

    ID channels, time/animation and parameter encoding are not yet fixed. No effect

    model or completed effects tensor is claimed.

EXTRACT-13 Full battle-path continuity

Deferred — hard discussion later. Connecting both bases through genuinely

passable terrain, pairing frontier contacts and sharing route sections remain

open. Do not solve it by drawing arbitrary links or calling witnesses lane counts.

EXTRACT-14 Every-map settings and default inventory

Large planned research task; dataset-wide, not five atlas maps. Inventory each

map's option IDs, types, choices/ranges, settings count, declared lobby defaults,

script fallback/effective defaults, dependencies, affected fields and source

logic. Mark unknown/dynamic behavior explicitly; author conventions differ.

A player's last-used lobby values are not map defaults. Settings count is not the

number of valid combinations. Preserve the default configuration first; later

support selected meaningful resource-poor/rich variants as distinct examples and

conditions. Do not enumerate all combinations or imply adaptive-map generation.

EXTRACT-15 Optional artificial data augmentation

Low priority; possible anti-memorization follow-up. Current terrain training

already rotates/reflections tensors through the inherited batch loader. Verify

alignment across all relevant model inputs, targets, masks, coordinates and

symmetry/effect metadata; other models may differ. Pixel shifting remains a

future option with safe padding/cropping and updated validity/labels, not toroidal

wraparound. Augmented/configured views are not new independent map families and

must not cross dataset splits. Do not claim augmentation guarantees no memorization.

Status and evidence rules

  • Owner-accepted layer flags remain unchanged; acceptance does not validate every

    default/runtime setting or model loader. EXTRACT-09 now explicitly needs rules.

  • Distinguish decisions from code, scientific data from previews, and recorded

    readiness from process liveness. No task closes from a rendering change.

  • Side-specific fields name actual source slots and the chosen transform/config.

  • Keep current exact-version historical evidence, while prioritizing the dataset

    and source models rather than particular atlas-map rendering gaps.
