Terrain Smoothing Investigation

What Causes the Faceting?

The full-map model predicts a 128x128 grid. A 10 km map is exported as 513x513 height vertices. Bilinear enlargement creates almost planar patches, with slope changes concentrated at the coarse sample boundaries. This is already visible in the saved heights, before resource placement or game rendering.

For Rot101 Refine250, native-grid curvature RMS is 0.05285 before file quantization and 0.05313 after it. Quantization changes heights by about 0.00195 world units on average. It is a secondary contribution, not the main cause of the large facets. The normal-map channels match the installed terrain shader's A/G convention, and normal maps are rebuilt from the exported geometry.

The model can also produce genuinely angular coarse hills. Uniform inherited materials make their lighting more obvious; engine level-of-detail may add its own effect. These tests do not establish a single cause for every visible artifact.

Optional Terrain Filter

supmapai.export.terrain_smoothing.smooth_native offers:

Preset Gaussian sigma in native/world units Purpose
none 0 Unchanged control, still the CLI default
light 2 Round coarse interpolation joints
medium 4 Stronger rounding, more loss of small relief

At 10 km/512 cells these sigmas represent approximately 39 m and 78 m horizontally. Smoothing happens before the validator flattens resource footprints. Normals are then rebuilt from the final quantized geometry, rather than blurred independently of the terrain.

Mixed-sign shoreline vertices and a two-vertex surrounding band are frozen; smoothing fades in outside the band. All vertex and cell land/water classifications must remain unchanged. Exact symmetry is restored and checked. A sign-preserving bound prevents new lakes/islands. There is no new procedural detail and no change to the model checkpoint or training dataset. This is deliberately not a shoreline slope limiter: steep coasts remain steep.

Four saved cases were compared with all three presets (12 comparisons). On Rot101 Refine250, before placement/quantization:

Filter Curvature RMS Mean height edit p95-p05 relief
none 0.05285 0 13.998
light 0.02511 0.03688 13.949
medium 0.01848 0.11301 13.828

These are diagnostics, not quality scores. Peak heights change more than the mean edit suggests. Light is the conservative review candidate; medium loses more small-scale detail. Neither can recover detail absent from a 128x128 model. Higher-resolution native training targets and a 256x256 model or learned detail refiner are possible later steps, not part of this change.

Reports and native-grid lighting comparisons: data/exports/terrain_smoothing_v1/report.md. These plots are scientific height-derived shading comparisons, not game screenshots.

Separate Resource-Pad Artifacts

The first smoothing exports still used legacy resource repair: a flat square footprint with a short, linear, square-shaped outer ramp. This can create visible square shelves independently of model terrain quality.

The new default pad profile, rounded, keeps the same required flat square core but uses distance from that core for a rounded outer blend. A quintic transition has zero first and second derivatives at both ends. Feather widths are doubled where there is room: spawn 8, mex 6, hydro 8 world units. This spreads the height adjustment instead of leaving a short sharp ramp. Local dry-clearance and overlap checks use the larger footprint; placeholder resources may move further to fit it. If placement fails, the entire placement pass retries with the old narrower widths but still the rounded quintic profile. It never relaxes dry/flat/symmetry checks. The actual multiplier and fallback flag are recorded in repair metadata.

All existing flat-core, exact symmetry and read-back checks still apply. The old repair is available as --pad-profile legacy. Broad terrain smoothing remains optional and is independent of this pad setting.

Export and Review

Two initial smoothed maps were installed with legacy pads: MapGen Symmetry Rot101 Refine250 Light and MapGen Symmetry Rot101 Refine250 Medium. The light version was directly launched and terrain rendering confirmed. Its log: data/exports/launch_logs/mapgen_sym_rot101_refine250_light_scenario_20261023_193959_427_utc.log. Both final exported maps have zero water vertex/cell classification changes relative to the original installed Refine250 map. The game still starts with an overly close camera, and empty texture-name fallback warnings remain separate follow-ups.

The subsequent rounded-pad candidate, MapGen Rot101 Smooth Pads, is installed as a separate map. It passed automated checks but has not yet been game-tested; the running session was left untouched. All four saved pilot terrains passed rounded-pad placement checks with light smoothing. The water-heavy seed303 case used the narrower rounded-blend fallback; the other three fitted wider blends.

Reproduce with:

$env:PYTHONPATH = 'src'
.venv-codex/Scripts/python.exe -m supmapai.export.symmetry_maps `
  --comparison data/models/terrain_symmetry_comparison_v1 `
  --template 'C:/Program Files (x86)/Steam/steamapps/common/FAF_modsmaps/maps/adaptive_canis_river.v0002/adaptive_canis_river.scmap' `
  --out-root data/exports/terrain_smoothing_pads_v1/maps `
  --case rotate180_seed101_water20 --method refine250 `
  --folder mapgen_sym_rot101_smoothpads.v0001 `
  --name 'MapGen Rot101 Smooth Pads' `
  --terrain-smoothing light --pad-profile rounded
./scripts/Install-SymmetryMaps.ps1 `
  -Manifest data/exports/terrain_smoothing_pads_v1/manifest.json

Use a fresh output root for another experiment; existing map folders are never overwritten. Close the current game before using the direct launcher:

./scripts/Launch-FAFMap.ps1 `
  -Scenario '/maps/mapgen_sym_rot101_smoothpads.v0001/mapgen_sym_rot101_smoothpads_scenario.lua'

To reproduce the terrain-only comparison, use the existing scientific environment (or install the project extras strategic,plots in a CPU analysis environment):

$env:MPLCONFIGDIR = Join-Path $PWD '.tmp/matplotlib'
.venv-codex/Scripts/python.exe -m supmapai.tools.compare_terrain_smoothing `
  --comparison data/models/terrain_symmetry_comparison_v1 `
  --out data/exports/terrain_smoothing_another_run

The comparison tool intentionally uses legacy pads when --template is supplied so its two exports isolate broad terrain smoothing. The single-map exporter defaults to rounded pads. No models were retrained and no community maps removed.
