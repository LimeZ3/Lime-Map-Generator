Pairing rules

  • Use actual ARMY_1 and actual source counterpart coordinates. Never rename, reposition or average starts. No ARMY_1 means unavailable.
  • Human selections override measured transform hypotheses. Human None/unsure does not silently fall back to detected symmetry. Their provenance is preserved.
  • Measured layout transforms use the existing 4-world-unit marker tolerance. Terrain-only and human hypotheses use the pre-existing strategy selector envelope of max(4 units, 5% of the smaller side). This is a scenario approximation, not a relaxed symmetry detection result.
  • Require nearest matching in both forward and inverse directions. Do not pair a spawn with itself. Ambiguous nearby approximate targets are left unresolved.
  • For several transforms, prefer mirror candidates with greatest base separation; if only rotations exist, prefer the angle closest to 180 degrees. Preserve the old pair among equally preferred options; deterministic residual/slot ordering breaks remaining ties, which remain listed as alternatives. This is a reproducible 1v1 scenario convention, not proof of intended teams.
  • A two-slot map may retain its only other slot with explicit unconfirmed status. Multislot maps with no assignable transform are not guessed. Owner exclusions remain excluded.

How many have the DualGap problem?

Fourteen kept maps have an old pair that is unsupported by the recorded transform candidates and a supported replacement (21 including exclusions). Thirteen use supported source layouts; one uses terrain-only symmetry, so even this is evidence about scenario consistency rather than proof of gameplay unfairness. Another 67 kept maps change by policy despite having symmetry-valid old pairs. Do not call all 81 changes confirmed errors.

DualGap itself is a separate archived 20km reference, outside this 10km audit cohort. Its actual source slots validate as ARMY_1 vs ARMY_2 under the new mirror preference. The historical 1-vs-12 setup can also be close to a valid rotational counterpart; symmetry alone cannot establish intended teams. The owner explicitly identified 1-vs-2 as the desired scenario.

Integration and validation

The executable selector is src/supmapai/extract/opposing_starts.py; regenerate the audit with PYTHONPATH=src python -m supmapai.tools.audit_opposing_starts. The audit binds the source cohort, saved detector results, source marker checksums and owner-curation snapshot. Six tests passed, including the real archived DualGap markers, incorrect slot numbering, fixed-axis self-matching, human approximation and ambiguous targets. Output coverage, distinct slots, owner exclusions and source hashes were checked.

data/processed/spawn_pair_audit_v1/setups.json is compatible with the existing versioned pipeline --setups input. Always pair it with --manifest data/processed/spawn_pair_audit_v1/eligible_manifest.json: that manifest contains exactly the same 1,247 selected kept maps, avoiding legacy-selector fallback for omitted cases. Its explicit active_slots are hashed into that pipeline run contract. Do not attach the new pair to old adaptive resource tensors: 81 kept scenarios changed and require new default/adaptive resolution, spawn channels, terrain-control measurements and all scenario-dependent strategy outputs before training. Existing tensors, ratings, source coordinates and checkpoints were left unchanged. The frozen 1.2.1 automatic selector was not edited.

Artifacts: receipt, data/processed/spawn_pair_audit_v1/pairs.csv, results.json, rebuild_required.csv, setups.json and curation_snapshot.json. Source curation remains live; a future dataset freeze must use a fresh pinned snapshot. No model training or expensive strategy rerun was started.
