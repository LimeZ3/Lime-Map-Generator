Map-relative reclaim tiers

Operating-policy update: the user fixed1s acquisition overhead and3 groups for subsequent work. Automatic-count and delay comparisons below are research history. See the current operating policy.

The local collection viewer now has Relative tiers: Automatic / Inspect two groups / Inspect three groups. Every nonzero-delay profile on the 11-map pilot has a map-level fit and a mass/work breakdown for each saved contact. Colored curve bands use the selected fit. The independent absolute rate probe remains available. No contact search, geometry, mass stock or mex/reclaim objective weight was changed. Zero delay remains a validation control without fitted tiers.

Reference and method

Reference stock is all known positive initial mass inside the playable bounds, under the same default active configuration. It includes starting/rear stock; route tables retain their earlier eligible own-side land-front scope. Common map boundaries prevent the same entity from changing tier merely because it belongs to a different path. Unknown values remain unknown and zero-mass objects are not classified as poor mass reclaim.

Use the existing mass-only timing hypothesis q=m/(m/25+d) and delays 0.25/0.5/1/2 seconds. Fit exact ordered one-dimensional breaks in log(q) by minimizing mass-weighted squared dispersion. Weight by mass rather than object count, without requiring any prescribed population fraction. Boundaries are geometric midpoints between adjacent observed groups. Preserve candidate fits for one, two and three groups.

Automatic selection uses explicit provisional dimensionless rules:

  • Weighted distribution silhouette at least 0.5.
  • Adjacent geometric rate centers separated by at least 1.5 times.
  • A third group improves silhouette by at least 0.05 over a supported two-group fit. If two groups fail but three pass the first two checks, retain three.
  • Otherwise keep two supported groups, or one unsplit group when neither split is supported. This is not a statistically calibrated confidence test.

The silhouette averages log-rate distances between quantity-weighted stock distributions, including zero distances for equal-rate stock. These selection constants are not learned gameplay thresholds. Two-group labels are Best available / Low priority; three-group labels add Okay. An inspected fit can fail automatic checks; the viewer states that explicitly. Low priority is relative opportunity, not zero utility or a measured player-APM/patrol recommendation.

First results

At 0.5s, auto selects three groups for Pandemonium Pass, Twin Rivers, Adaptive Diversity and Adaptive Monument Valley; the other seven maps select two. At 2s, Pandemonium and Adaptive Tabula Rasa select three; the other nine select two. Thus automatic group count still needs interpretation and sensitivity review.

Twin Rivers' top-group boundary is about 3.28 mass/engineer-s at 0.5s, versus 16.75 for Wonder Open. The relative method promotes modest chunks when the map's alternatives are poor without changing their absolute collection rates.

Adaptive Tabula's three-group interpretation is particularly useful. Balancing against mexes and energy

Tier quality, resource quantity and economic significance are distinct. The viewer exposes each tier's mass, work and mass-equivalent configured T1 income seconds (stock / active-map T1 mex income proxy). This is a descriptive stock versus flow comparison; it assumes neither immediate collection nor a universal reclaim:mex exchange rate. Current objective weights remain unchanged.

The next balance experiment should choose an economic window T and explicit engineer work budget B (eventually accounting for travel). Compare collectable mass M(B) with continuing production I_mass*T, rather than counting all raw stock as immediately available. Existing stock/flow weighting can then be tested with this collectable stock. Neither tier ordinal numbers nor automatic group count should become arbitrary objective multipliers. Keep best/okay/low amounts separate so a large cheap tree tail cannot hide a valuable core.

Energy needs the same inventory -> per-entity work -> reward curves -> map-level tiers -> economic-context stages, but shares physical collection work with mass. The reusable tier fitter accepts any positive resource rate and quantity, with no hard-coded mass units. Inventory CSVs now include energy-only objects, zero values and unknowns. Across these maps there are 8419 known zero-mass, positive-energy entities; 7241 are in Pandemonium and contain all its known energy reclaim (30849 energy). The playable-area Diversity inventory contains 634 energy-only objects (2400 energy); the earlier extraction-wide count of650 also included objects outside playable bounds.

Do not compute energy work as energy/25 or add a second acquisition charge. The inspected current FAF Prop.lua describes one operation whose source estimate uses the larger mass/energy value, the reclaimer's build rate and the prop's reclaim-time multiplier. Blueprint timing fields and the matching pinned source rule need a source-audited timing pass before publishing energy efficiency tiers. This also motivates comparing the current user-supplied mass/25 hypothesis with a joint-resource timing model; we have not silently replaced the reviewed mass model with a new one.

An entity should ultimately carry a joint reward (mass, energy) with one shared work cost. Mass-first and energy-first collection schedules can differ, so their separate best-first curves cannot both be claimed simultaneously for one engineer budget. Compare mass-limited, energy-limited and balanced economic scenarios; energy income/storage assumptions must be explicit, without a fixed mass:energy exchange rate. Overflow and shortages affect usefulness even when stock quality is unchanged. No energy efficiency tier or energy-aware route weight is claimed complete in this round.

Exports and validation

Each map has relative_tiers.json, relative_tier_metrics.csv and resource_inventory.csv. Models retain their selection evidence and exact reference scope. All sources, existing result/curve inputs and tier code are fingerprinted. Route/base/all-pool stock, work and fractional entity ownership are conserved for every candidate model.
