Full-map 256 Terrain Training V3

Water Fix

The saved 28-sample steering sweep isolated the main loss to averaging signed water-distance fields for symmetry. In the medium setting, raw model coverage was 19.55%, averaged coverage 8.21%, and refined coverage 8.36%.

The versioned export.terrain_water.finish_terrain decoder carries the raw model's predicted wet-cell count through symmetry and any optional refinement. It reuses the existing water-aware orbit ranking, rebuilds consistent signed shore distance/height/depth, reconstructs native vertices, and applies the shoreline-protected light filter. It never reads the requested water percentage. This is deterministic postprocessing, not proof that a model predicts the exact requested area. It can change shorelines and does not guarantee connectivity.

All 28 archived cases passed the regression: maximum final cell-centre water-area error is 0.394 percentage points relative to the raw prediction. Mean coverages:

Setting Raw prediction Previous final terrain Corrected final terrain
Low water 2.00% 0.43% 1.97%
Medium water 19.55% 8.28% 19.45%
High water 48.32% 47.55% 48.23%

Evidence: data/models/terrain_water_fix_v2/audit.json and restored_water.png. Historical model outputs/checkpoints are preserved. New V3 training galleries use this decoder; the historical V1 comparison tools remain historical references rather than silently overwriting their results.

Why Another Dataset Build Is Necessary

The newly completed label release, data/tensors/terrain_half_10km_1v1_controls_v2, labels four rotated half-map completions of each 128-grid map. Those profiles are scientifically incompatible with the requested full-map 256 model. They cannot be copied onto full targets.

V3 reuses that exact cohort and family assignment: 1,200 train / 110 validation. It rebuilds all full-map targets from the original checksummed 513x513 height vertices and 512x512 depth arrays stored in the strategy tensor archives. It does not upscale the 128-grid model targets. Native metadata and height reference are verified by reproducing the old 128-grid source height channel. No original .scmap extraction or 6,000-map scan is needed.

Full native physical heights, coverage and depth are pooled to 256 and encoded with the existing frozen train-only physical scales. Clipping fractions are recorded. Spawn fields preserve the previous physical Gaussian width: sigma eight model cells at 256, rather than four cells at 128.

Direct controls are remeasured from each exact decoded 256 target reconstructed at native resolution, using the original selected opposing bases. No half crop, imposed symmetry, learned refinement, resource pad or smoothing enters labels. The same ten-field schema distinguishes total front width, largest span, fragmentation, absolute sustained bottlenecks, relative contraction, restriction duration, water, relief and connectivity. Unavailable widths stay masked. Only training examples fit the new control scaling. No test split is read.

The durable builder has per-map leases, source/code signatures, resumable checksummed completion records and full measurement evidence. A complete audit and published release are required by the new loader. A failed map is not silently dropped. Two CPU workers are used. Source and half-map artifacts stay unchanged.

Dataset: data/tensors/terrain_full256_controls_v3.

Training Configuration

  • Full 256x256 output: joint relative height, water SDF and depth.
  • Two spatial requested-base fields; 21 profile entries (ten values, ten masks, water-enabled flag). Legacy economic profile coordinates are not reused.
  • Fresh 2,988,787-parameter U-Net, base width 48, global bottleneck attention.
  • Velocity objective, existing auxiliary terrain losses, bfloat16, AdamW, EMA, gradient clipping, warm-up/decay and family-balanced sampling.
  • Bounded 12,000 updates at batch 16: 192,000 presentations.
  • Validation every 1,000 updates, preserving last.pt and validation-selected best.pt. PNG galleries every 4,000 updates and at completion.
  • No final resource/prop/texture training, game installation or game launch.

The old 13-condition checkpoints cannot be resumed as this new 21-condition model. Training starts fresh. Higher resolution and compute do not guarantee better quality or steering. Validation, fresh samples and remeasured controls are still needed before judging success.

The RTX 5080 probe at batch 16 passed finite forward/backward updates, using about 6.9 GB peak allocated memory and 0.154 seconds per update after warm-up. That suggests roughly 31 minutes of update compute, excluding real-data loading, validation, checkpoint writes and gallery generation. It is not an overall ETA. Dataset geometry measurement is a separate CPU phase.

Persistent Run

Run folder: data/models/terrain_full256_controls_v3. The hidden local runner automatically starts training only after dataset audit and a fresh GPU probe pass. It refuses a changed pipeline contract on resume, holds an OS lease against duplicate controllers, and reports failures instead of silently continuing. It does not schedule a cloud job or purchase compute.

./scripts/terrain256-training.ps1 -Action Start
./scripts/terrain256-training.ps1 -Action Status
./scripts/terrain256-training.ps1 -Action Pause
./scripts/terrain256-training.ps1 -Action Resume

Dataset pausing drains active maps. Training pausing checks every 100 updates, evaluates and saves a checkpoint before stopping. Resume keeps the original 12,000-update total, optimizer state and learning-rate schedule. A completed run is not extended by resume.

Inspect pipeline.json for phase, heartbeat, child PID and logs; dataset status.json for map counts; and training progress.json for steps, throughput and provisional training ETA. Logs are under the run's logs/ folder. Checkpoints are atomic. Galleries include raw versus final water coverage so postprocessing drift is visible.

At dispatch on 24 October 2026, the first four native conversions, both GPU batch-size probes, 28-sample water regression and the full 391-test suite passed. The dataset/training pipeline was started; these checks are not a claim that the full preparation or training run has completed. Live status files are authoritative.

Completed Run and Control Test

The complete 1,310-map preparation finished and all 12,000 training updates completed successfully. Training took 34 minutes, with best validation loss 0.01047; that is a denoising diagnostic, not a map-quality score. The final 12-sample gallery retained learned water area within 0.1 percentage points.

The subsequent 32-sample direct-control test shows a clear fragmentation response, modest raw front-width response weakened by postprocessing, and unreliable bottleneck/disconnection control. It does not justify calling all controls reliable. No further training was started.
