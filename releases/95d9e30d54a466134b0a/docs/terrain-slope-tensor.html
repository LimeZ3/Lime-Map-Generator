Physical terrain slope tensor (EXTRACT-05)

Implemented and extracted 27 October 2026. This is a numeric supporting tensor, not an additional trained stage. Existing terrain, texture and resource checkpoints, their input channels and their selected loss functions remain unchanged.

Definition and model role

For physical height h, slope is sqrt((dh/dx)^2 + (dh/dz)^2): vertical world units per horizontal world unit. It is an unsigned steepness magnitude, not a compass direction and not a passability label. A rise of 0.75 per horizontal unit gives slope 0.75. The bounded model encoding is atan(slope) * 2/pi; slope 1 maps to 0.5. This physical angle encoding has no learned scale or train/validation statistic fit.

Height remains authoritative geometry. Downstream texture/resource models can derive this channel from the actual upstream terrain available at inference. For terrain generation, use slope calculated from predicted clean height as an auxiliary supervised output/loss. Do not feed clean target slope to an unconditional terrain model. No new loss weight or training run was selected here.

Saved arrays

Every map has maps/<key>/slope.npz. All arrays are 1 x 256 x 256.

Array Type Meaning
slope float32 Physical rise/run from native cell heights pooled to 256 before differentiating
encoded float32 Fixed angle encoding of source slope, in [0,1]
valid bool Source derivative validity
target_slope float32 Physical slope from the exact decoded saved 256 terrain-height target
target_encoded float32 Bounded auxiliary target corresponding to the represented terrain height
target_valid bool Target derivative validity; saturated height neighborhoods excluded

The current corpus has 512 x 512 native cells, giving 2 world units per tensor cell on both axes. Native vertices are averaged into native cells, then cells are mean-pooled to 256. Slope is taken after pooling. Averaging high-resolution slope is a different quantity and is not used as hidden supervision. The target branch decodes the exact frozen asinh height field at the same resolution. It does not reconcile water channels, upsample, force symmetry or use native-detail gradients that the represented height cannot contain.

Central differences require the centre and its four cardinal neighbors. The outer one-cell tensor border is invalid. Physical playable bounds are checked by whole cell footprint; derivatives crossing padding, nonfinite height or the playable boundary are invalid. Invalid values are stored as zero with mask false; valid flat terrain is zero with mask true. Target height saturation masks its derivative neighborhood. No maps in this cohort had saturated saved height targets.

Underwater terrain uses the same physical height field and derivative; the water surface is not substituted for terrain. Slope alone is not an engine navigation grid. Narrow cliffs may be smoothed by 256-grid height pooling, which is why the native pathing analysis remains separate.

Collection, eligibility and provenance

The extraction covers the original 1,310-map audit cohort: 1,200 train / 110 validation, with no held-out test maps. All 1,310 completed with zero failures in 63.82 seconds of build/finalization time (initial source-contract preparation is separate).

The pinned latest owner snapshot has 1,255 kept / 55 excluded. Excluded maps retain arrays for auditing but cannot enter the role-filtered training manifests. The existing curated terrain release has 1,117 recorded members; intersecting it with current owner exclusions leaves 1,112 current-role examples: 1,018 train / 94 validation. This does not silently expand the selected training cohort to 1,255 maps or create a newly approved training dataset. The EXTRACT-06 field audit and release freeze are still pending.

The source is data/tensors/terrain_full256_controls_v3; output is data/tensors/physical_slope_256_v1. all.jsonl includes all source records and explicit eligibility. train.jsonl and validation.jsonl contain the current-role/owner-kept intersection. Each row records key/family/split, array hash, source hashes, spacing and statistics. The sealed release lists artifact hashes. The build contract pins source release, target normalization, owner snapshot, bounds records and implementation. Code snapshots are saved in the release.

Validation and available code

Seven tests passed, covering a known 3-4-5 physical plane, non-square spacing, additive height shifts, quarter-turn consistency, padding and missing values, angle encoding, NumPy/Torch parity and finite backpropagation on both sloping and flat terrain. Three real-map smoke extractions passed: (-X-), Adaptive Twin Rivers and water-heavy 3v3 Winter Expanses. The initial Canis smoke request was outside this 10km source cohort; no replacement version was silently substituted.

All 1,310 saved archives were independently checked for hashes, shapes, float/bool types, finite/nonnegative values, encoding parity, invalid zeros, boundary masks, role exclusions and family separation. Source pooled height and decoded target height differ by at most 0.0000701 world units on usable cells. Small floating-point representation differences remain separate from physical definition differences.

  • Pure NumPy extraction/encoding and differentiable Torch helper: src/supmapai/tensors/slope.py.
  • Optional masked_slope_loss: masked L1 between predicted physical-angle slope and target; implemented and tested, not added to an existing model loss. Sensitive nonlinear height decoding runs in float32 for mixed-precision callers.
  • Resume-safe builder: PYTHONPATH=src python -m supmapai.tools.extract_slope_tensors --workers 2. Completed signatures are checked; failures remain explicit and are not automatically retried. Use a new output version if the source/code contract changes.
  • Liveness: data/tensors/physical_slope_256_v1/status.json; numerical checks: audit.json and validation.json; atlas receipt.
