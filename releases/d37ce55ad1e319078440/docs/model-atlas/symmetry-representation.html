EXTRACT-07 — proposed symmetry conditioning representation

Design proposal, not implemented or measured. The owner requires symmetry to be available as a training/generation condition: "this map is symmetrical in this way." This note proposes the encoding; it does not freeze a tensor schema, run the detector, change existing checkpoints/loaders or start training.

Source-first acquisition; no universal stored symmetry label

The standard SCMAP layout handled by the FAF editor's loader and our vendored structural reader has no documented symmetry-type field to read as a universal class. It stores final terrain/material/entity data. The local Adaptive Canis River scenario was also checked: it declares size, starts and team configuration but no symmetry field. This is not a count or audit of custom declarations across the whole dataset.

Acquisition proposal:

  1. Inspect source declarations, custom metadata, supported generator receipts or other explicit source evidence first. Preserve the exact declaration and provenance; do not assume all authors use a shared convention.
  2. Where supported declarations exist, normalize their meaning and verify them against the relevant map/configuration/domain. Declared intent and measured agreement are different evidence states. Missing, conflicting and stale metadata must remain explicit.
  3. Infer missing/unusable symmetry from geometry and corresponding source starts, with resource/default-setting agreement recorded separately as appropriate.
  4. Cache the descriptor and evidence by source identity/configuration/domain and method version. Training, generation tooling and the dataset viewer consume this saved data; no symmetry discovery is run per training batch. Changed source/configuration or extraction contract invalidates the relevant cache.

No full-dataset metadata inventory or symmetry detector has been run for this proposal. A map-specific metadata hint is not yet a verified dataset label.

Recommendation: structured descriptor encoded as a vector

Use an interpretable class/ID for cataloging, together with geometric parameters. The model receives a numeric conditioning vector produced from those fields. An arbitrary integer ID on its own cannot express an angled/offset mirror axis or distinguish all multi-axis/sector configurations. This is global map data; it need not initially be a full image-sized channel.

Stored field Meaning Model representation proposed
family none, reflection, rotation, rotation_with_reflection Categorical embedding or one-hot; no ordinal scalar
rotation_order n-fold rotation: 2 means 180 degrees, 3 means 120, 4 means 90 Categorical code/embedding for supported orders; retain integer in metadata
center_world / normalized center Common rotational center, or canonical point on a single mirror axis Two continuous coordinates plus validity
reference_axis_angle Orientation of one reflection axis, when reflection is present Periodic phase pair, not raw degree scalar
validity Which type/order/center/orientation labels are known Availability flags / explicit unknown control
fit_evidence Per-transform/per-layer errors, confidence, tested domain and settings Audit/eligibility data; not a requested softness control

The order vocabulary, embedding dimensions and final vector length are selected when the supported schema/detector scope is fixed. No fixed upper sector count or new profile width is silently added to the selected 21-value terrain model. Unknown/uninformative detection must remain distinct from a confident "none."

Multiple axes without a growing list of arbitrary IDs

For a consistent finite planar symmetry group, rotations are generated by a sector rotation; adding a reference reflection generates the corresponding mirror axes. The compact descriptor follows this structure; see the planar rotation/reflection generators. Approximate candidate transforms must still be validated as a consistent selected group, not labeled as exact merely because each separately passed a loose test.

Examples below are synthetic encoding examples, not detected map labels:

Request Family Rotation order Reflection information
One vertical mirror reflection 1 (identity rotation only) Axis angle 90 degrees, if +world-x is zero
Half-turn only rotation 2 None
Horizontal and vertical mirrors rotation_with_reflection 2 One axis generates both perpendicular axes
Three repeated sectors, no mirrors rotation 3 None
Three sectors plus three mirrors rotation_with_reflection 3 One reference axis generates three axes
Four sectors plus four mirrors rotation_with_reflection 4 One reference axis generates four axes

Do not assume a pizza-shaped arrangement has mirrors: it can have rotation only. Retain the expanded axis/rotation/transform list and validation evidence in metadata even if the model uses the compact parameters. A detector that cannot fit a consistent supported descriptor records unresolved evidence rather than silently discarding additional axes or forcing a category.

For a group with n reflection axes, reference angles differing by pi/n denote the same axis set. A canonical phase encoding is:

[cos(2*n*theta), sin(2*n*theta)]

For a single mirror n=1, so this reduces to the usual unoriented-line encoding. It avoids both wraparound discontinuities and multiple equivalent reference-axis labels for the same group. Center coordinates are normalized using the declared map domain; angles/transforms retain their world-coordinate meaning. Non-square normalization must not turn a physical reflection into an incorrect image-space operation. For one mirror only, choose a canonical point on the line (e.g. the projection of the domain center onto it); an arbitrary along-axis coordinate is not separately identifiable.

Rotation-only groups need a center and rotational order, but no reflection-axis angle. Control of where a sector's specific contents begin would be an additional layout/orientation condition, not information supplied by the rotational group alone. Planned starts and other layout fields remain separate inputs.

Training and inference roles

  • Training: detect/validate the descriptor for the actual source configuration and domain; provide it as a condition alongside the relevant model data. Store per-layer agreement so a symmetric heightmap does not automatically certify asymmetric resources or an unresolved settings variant.
  • Generation: the requested descriptor is supplied by the user/configuration, not extracted from a map that has not yet been generated. Use the same declared description throughout relevant stages. New inputs require a newly trained compatible model; existing checkpoints do not consume this proposal.
  • Augmentation: transform centers, axes, source-start correspondences and any derived spatial fields together with the map. Do not rotate a height target while leaving a vertical-mirror condition unchanged.
  • Validation/enforcement: a conditioning vector encourages the learned property but is not a mathematical guarantee. The recorded transforms should also drive symmetry checks and explicit enforcement where required. Raster interpolation/domain boundaries must be accounted for at arbitrary angles.

The valid/playable domain is explicit. Container boundaries, non-square areas and a radial arrangement's valid region cannot be ignored when testing symmetry. Near-symmetric or locally symmetric maps retain their tolerances and domains; partial evidence does not silently become a full-map exact label.

Viewer and spatial fields

The dataset viewer should expose the stored type, order, angles, center, validity, confidence and source/configuration. Axis/center diagrams are derived from that same descriptor rather than independent hand-authored labels.

Rasterized axes, center distance or sector-coordinate fields are possible future spatial conditions if a bounded model comparison justifies them. They are not necessary to preserve the global instruction initially. A line mask alone loses type/order distinctions and cannot represent rotation-only symmetry clearly.

The viewer's audit population and curated model subsets already have separate identities. Adding this field must preserve those memberships and mark pending or unavailable detections honestly, rather than presenting a viewer annotation as a new frozen model-data release.
