Terrain-control relabeling of the latest training cohort

The latest actual training run was data/models/terrain_half_10km_1v1_v1. It trained on data/tensors/terrain_half_10km_1v1_v1: 1,200 training maps and 110 validation maps. Later full-map steering outputs were inference experiments, not newer training sessions. This run relabels that exact 1,310-map cohort.

Output: data/tensors/terrain_half_10km_1v1_controls_v2. Original terrain archives, old manifests, normalization, family splits and model checkpoints remain unchanged. No test manifest is read. No training is launched.

Completed release — 24 October 2026

All 1,310 maps / 5,240 rotated-half variants completed with zero extraction failures. Processing and publication took 1 h 55 min 13 s. The final audit passed and the release is ready at the output path above. A separate post-run handoff check verified all eight release artifact hashes, every source and label archive through the real training loader, the unchanged 1,200/110 split, separation of 1,212 families, validity totals, and eight augmented CPU batches. It is recorded in handoff_validation.json. No model training was performed.

Water, relief and connectivity are available for every variant. Width and bottleneck measurements are available for 4,594 / 5,240 variants. Their masks are false for 606 disconnected pairs, 28 blocked-base pairs and 12 connected pairs with insufficient interior distance after the base buffer. These are retained maps with explicitly unavailable labels, not extraction failures or discarded training examples. Read these statuses as properties of reconstructed half-map targets, not claims about the original native maps.

Measurements and target representation

See the measurement specification. Ten scalar controls keep water coverage, robust relief, land connectivity, typical total traversable front width, largest uninterrupted width, fragmentation, sustained bottleneck total and largest width, relative contraction, and restriction duration separate. No economic openness, resources or route-witness/attack-lane count enters this conditioning profile. A broad front and several narrow spans remain distinct.

Labels describe the actual 128×128 encoded terrain used by the half-map experiment, decoded and deterministically reconstructed on its 512-unit map. Four rotations select four different north halves; each is completed with its 180-degree copy. No join repair, learned refinement, smoothing or passage carving is applied. Horizontal flips reuse scalar labels; reflection was checked on six sampled source maps, with unchanged connectivity and only a small grid-level width difference (about 0.002 units in one sustained bottleneck). This is not proof of exact floating-point invariance on every map.

Native source-resolution paths may differ from these model-visible paths. Hidden terrain-type blocking, props, scripted walls and movement modes other than land are not observable targets. Disconnected or blocked bases yield masked widths; they do not mean an arbitrarily narrow front. No bases are snapped onto land. Maps with unmeasurable geometry remain explicitly identified. These measurements are geometric estimates, not engine pathfinding or certified military lanes.

Durable execution

From the project directory in PowerShell:

.\scripts\terrain-relabeling.ps1 -Action Prepare
.\scripts\terrain-relabeling.ps1 -Action Resume
.\scripts\terrain-relabeling.ps1 -Action Status
.\scripts\terrain-relabeling.ps1 -Action Pause

Resume launches a hidden persistent supervisor. Use it again after a deliberate pause; completed per-map results are reused. Two workers are used. Supervisor, controller and per-map OS leases prevent overlapping controllers and workers; the supervisor retries controller crashes at most three times and respects pause requests. It never retries a map marked failed. A pause drains active maps, then stops scheduling. The status contains a heartbeat, completed counts, active map keys, elapsed compute-session time and a provisional remaining-time estimate. Logs are under .local-tools/terrain-relabeling; controller/worker tracebacks remain inside the output directory. A restart does not change extraction settings.

Pinned code and input signatures must match on resume. An intentional scientific change requires a fresh output version. All maps must complete before publication; failures set needs_attention and prevent a training-ready release. Do not use partial measurement files as training inputs.

Published artifacts and next training

  • terrain_controls.csv: physical measurements for all 5,240 rotation variants.
  • measurements/<key>/variants.json.gz: full measurement and cross-section evidence.
  • controls/<key>.npz: four raw-value arrays, validity masks and conditioning vectors.
  • normalization.json: scaling fitted only on training variants, never validation.
  • train.jsonl, validation.jsonl: the exact original cohort and family splits, referencing unchanged source targets plus new label archives.
  • audit.json, release_manifest.json: validation and checksums required by the new loader. The release exists only after a successful complete audit.

The new profile has 21 entries: ten scaled geometry values, ten validity flags, then the water-enabled flag. Values without valid measurements are encoded zero with validity zero. This is conditioning validity, not an additional scalar loss. The existing diffusion terrain losses remain unchanged.

Use supmapai.ml.terrain_control_half.RelabeledHalfTerrainDataset, which selects the profile matching the sampled rotation. Old 13-condition checkpoints cannot be resumed with the 21-condition architecture. The new training entry point is:

$env:PYTHONPATH='src'
.venv/Scripts/python.exe -m supmapai.ml.terrain_control_half --dataset data/tensors/terrain_half_10km_1v1_controls_v2 --out data/models/terrain_half_10km_1v1_controls_v2

This is a handoff command, not a command executed during relabeling. Legacy economic-profile galleries are disabled in this versioned trainer because their profiles are incompatible. New control-conditioned generation comparisons are future work. The profile dimension and code hashes are recorded in a new run's configuration. Dataset checksums and audit are checked before it can be loaded.
