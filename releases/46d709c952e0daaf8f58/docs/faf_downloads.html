Folder identity plus .scmap and scenario-file presence establish existing-map matches; these are not hash-verified.

Catalog fields

  • map_id, version_id, folder_name: identifiers for joins, not display names.
  • display_name, description, width, height, max_players, version, map_type, battle_type: grouping and extraction inputs.
  • hidden, ranked, recommended, play counters, upload/update dates, ratings, review counts, author and license IDs: preserved vault metadata.
  • download_url, thumbnail_small, thumbnail_large: original source URLs.
  • local_relation: latest present, different version present, or no known local version.
  • download_status: existing_local, pending, downloaded, failed, or missing_latest_reference. Downstream jobs should select existing_local/downloaded.
  • local_path: actual map directory; never assume the map is directly under one root.
  • scmap_paths, scenario_paths, save_paths, script_paths, preview_paths: JSON arrays inside CSV cells. Preview paths list candidate local image files, which can include textures; semantic preview selection happens downstream.
  • archive_path, archive_bytes, archive_sha256, completed_at: verified-download provenance. Blank for pre-existing maps that have not been archive-verified.
  • attempts, error, snapshot: progress and provenance.

CSV is UTF-8 with BOM, standard quoting and spreadsheet-formula escaping. Parse arrays as JSON after parsing the CSV. The original raw API JSON remains in the vault snapshot. Review text remains in that snapshot's exports/mapVersionReview.jsonl, joined by version relationship; it is not duplicated in each catalog row.

progress.json summarizes counts and bytes. Per-map results/*.json is checkpointed after every attempt; the CSV is refreshed every 25 attempts and on normal exit/pause. archives/ retains ZIPs and maps/<map_id>_<version_id>/ contains extracted files. Downloads run serially with a one-second gap, without map-database queries. HTTP 401/403/429/503 or three consecutive failures pause the run. There are no immediate automatic retries. A later explicit resume can retry failed entries up to three total attempts. Respect server cooldowns before resuming a throttled run.

Archives are size-limited, CRC-checked while extracting, checked for unsafe paths and symlinks, and installed via a staging directory. Existing installations are never overwritten. The process pauses with less than 15 GiB free. It uses no FAF credentials.

Prepare or resume

For a live status display, double-click scripts/Watch-FAF-Downloads.cmd. It refreshes every five seconds and checks whether the downloader process exists, the saved run state, counts, last logged map and log activity age. More than five minutes without a completed-map log is flagged for inspection, not declared a failure. Closing this monitor does not stop downloads. The launcher sets PowerShell execution policy only for its own process; it does not change the machine's policy.

One-time status: powershell -NoProfile -ExecutionPolicy Bypass -File scripts/faf-download-status.ps1.

$env:PYTHONPATH='src'
.venv-codex/Scripts/python.exe -u -m supmapai.tools.faf_download --snapshot data/raw/faf_api/entire_vault_20261008 --output data/raw/faf_maps/latest_20261008 --local-root 'C:/Program Files (x86)/Steam/steamapps/common/FAF_modsmaps/Allmaps' --local-root 'C:/Program Files (x86)/Steam/steamapps/common/FAF_modsmaps/maps' --run

Omit --run to refresh the catalog without network access. A .download.lock prevents two runs from writing simultaneously. After an abrupt termination, verify its recorded PID is no longer running before removing the lock and resuming. Completed results are reused; an incomplete .part file restarts from zero. Keep the PC awake for long runs.
