Entire vault collection (2026-10-08)

The user expanded the scope to every accessible map in the FAF vault, including maps absent from the local library. Use:

$env:PYTHONPATH = 'src'
.venv-codex/Scripts/python.exe -m supmapai.tools.faf_vault_all --output data/raw/faf_api/entire_vault_20261008 --max-requests 2000 --run

This is a serial, five-second-paced crawl of map, mapVersion, and mapVersionReview. No local-folder, visibility, ranked, map-generator, or date filter restricts its scope. FAF's access controls still determine which records are readable. No game/replay endpoints or map archive downloads are used.

Three discovery queries establish each collection's record count and highest ID. Subsequent requests advance by ID up to that ceiling, avoiding shifting page offsets and excluding new uploads beyond the initial fence. Each resource has its own discovery timestamp, so this is not a transactional database snapshot. Edits/deletions during collection remain possible. Totals are requested only during discovery. The client stops on HTTP errors, throttling, 30-second network timeouts, oversized responses or response latency over 15 seconds. It does not retry automatically. A supplied Retry-After cooldown is persisted.

The larger request budget replaces the old 20-request calibration cap for this explicitly authorized whole-vault crawl; it does not increase concurrency or request rate. The first count queries print an estimated number of pages and pacing duration. If the token expires, the run pauses and exports its partial results; the same command resumes after browser login. Credentials remain in memory only.

manifest.json records per-resource progress and run history. pages/ retains raw requests/responses. vault.sqlite3 indexes primary and included resources by (type, id); it is the resumable working database. Keep it together with the manifest and cached pages. exports/ is generated at completion or a controlled pause and contains:

  • maps.csv: one row per parent map, lifetime parent plays plus latest-version metadata/status.
  • versions.csv: every collected version, including exact-version ranked status, dimensions, slots, description, dates, review summaries and parent/version play counters.
  • map.jsonl, mapVersion.jsonl, mapVersionReview.jsonl: original primary JSON:API resources and their relationship linkage.
  • local_library_matches.json / .csv: links back to the local catalog. These remain provisional until the version catalog is complete.
  • summary.json: discovery totals, collected counts, per-resource completeness and local-library coverage.

The previous folder-targeted commands remain usable for their own cached snapshots, but the whole-vault crawl uses a new directory to keep scope and provenance clear. Some previously sampled records will be fetched again as part of this consistent catalog pass. Raw content and SQLite data remain in the Git-ignored raw-data directory.

Live discovery on 2026-10-08 returned 14,811 parent maps, 32,213 versions and 6,900 reviews. Highest-ID fences are 15,313, 33,034 and 7,883 respectively. This is approximately 544 requests including discovery, or 45–50 minutes at the configured pace. These are discovery totals; completion is determined separately in the manifest and export summary.

After completion, verify the saved catalog offline:

$env:PYTHONPATH = 'src'
.venv-codex/Scripts/python.exe -m supmapai.tools.faf_vault_audit data/raw/faf_api/entire_vault_20261008

The audit writes exports/audit.json, checking saved/discovered counts, resource links, required version fields and ranked coverage. It also reports differences between FAF's parent counters/summaries and sums from versions/raw reviews; it does not silently replace the source values.

Current direction: map vault only (2026-10-07)

The user replaced replay-history collection with the vault's all-time play counter. All game-history plans and calibration commands below are historical notes. Use the new vault-only entry point:

$env:PYTHONPATH = 'src'
.venv-codex/Scripts/python.exe -m supmapai.tools.faf_vault --output data/raw/faf_api/library_calibration_20261006 --max-requests 20 --run

This reuses cached vault pages and performs only map-version lookup and map-review requests. It never requests games, featured modes or replays. Omit --run to regenerate exports from cached vault responses without login or network access. The snapshot's older folder name and original calibration metadata remain for provenance; new manifest runs are labelled map_vault_only. The old replay records are retained but excluded from the vault exports.

vault_exports/maps.json and maps.csv contain one row per library map, including pending rows with null API values:

Field group Exported information
Identity Local ID/folder, exact FAF version ID, parent map ID, version number, display name, latest-version relationship ID
Usage Parent all_time_plays, exact-version version_all_time_plays
Competitive status Exact-version ranked and hidden; parent recommended
Size and slots Raw API width/height and maximum players
Dates Parent and exact-version creation/upload dates and update timestamps separately
Community ratings Parent and version average, count, score sum, lower bound, positive/negative components
Other metadata Description, map/battle type, author ID, licence ID, download URL and small/large preview URLs

Dimensions remain in API map units (e.g. 512 corresponds to the conventional 10 km map dimension), rather than silently being labelled kilometres. A parent creation date and a version upload date are different events. recommended, ranked and community stars are independent signals.

Author names and licence details are available through additional relationships in the API source, but the current lookup includes only their IDs. Missing metadata/rating summaries remain null. Community text and star ratings remain in vault_exports/reviews.json; summary.json records matching, ranked/unranked counts and review completeness. CSV neutralizes spreadsheet formula prefixes in text; JSON preserves original text.

Ranked status is attached to a version, not to the entire parent map forever. ranked=false means the version is not enabled for ranked play; it does not identify the reason. FAF's creative-team explanation discusses author choice at upload and balance, functionality or exploitation reasons. Use the flag as a competitive-dataset eligibility filter, not as automatic ground truth that the map is technically broken. Likewise, ranked=true is not an independent guarantee of quality.

The primary usage signal is now FAF's unfiltered all-time parent counter. It is not restricted to two-human/five-minute games, and it must not be summed repeatedly across local versions of the same map. Exact-version usage is retained for comparison. Unranked maps are collected rather than discarded, so the downstream dataset can apply a transparent filter.

Both legacy replay entry points reject --run after this change. Their parsing/helpers remain available for the recorded calibration and tests. Nineteen offline tests passed when the vault entry point was introduced.

Run from the MapGen repository root with Python 3.11 or 3.12. No additional packages are required. This is a bounded pilot collector, not a validated full-history exporter.

$env:PYTHONPATH = 'src'
.venv-codex/Scripts/python.exe -m supmapai.tools.faf_collect --start 2026-10-05 --end 2026-10-06 --output data/raw/faf_api/pilot_20261006

Without --run, this only prints the plan. Dates refer to game start time in UTC, inclusive start and exclusive end. Map/version/review collection is not date-filtered. Change dates and output directory for another pilot.

To sign in through FAF and sample one page from each resource:

.venv-codex/Scripts/python.exe -m supmapai.tools.faf_collect --start 2026-10-05 --end 2026-10-06 --output data/raw/faf_api/pilot_20261006 --max-requests 4 --run --login

The browser flow uses Authorization Code + PKCE, validates state on a loopback listener, and requests openid public_profile. It uses the public native-client ID found in the Rust client's source. This is not a newly registered MapGen OAuth application or an endorsement from FAF; deployment acceptance and allowed scopes must be verified. An authorized alternative client ID can be supplied using --oauth-client-id or FAF_OAUTH_CLIENT_ID. Login expires after three minutes. Tokens and callback codes are not written to files or logs, and refresh tokens are not requested or persisted. Complete login in FAF's browser page, not in chat.

Alternatively, provide a valid access token through the hidden local --prompt-token prompt or the process environment variable FAF_ACCESS_TOKEN. Do not put a token in a command argument, source file, screenshot or chat message.

Repeat the same command and output directory to resume. A different query plan requires a new directory. Login is required again for each browser-authenticated run. Exit code 2 means paused or incomplete, including the normal request-budget stop; exit code 0 means all four collections reached terminal pages. An expired login stops collection and does not initiate automatic retries.

Limits and outputs

  • One outstanding API request, at least five seconds after each completed response.
  • Default maximum 20 API requests per invocation; hard ceiling 20. Authentication exchange is separate.
  • Game windows of at most seven days; page size at most 100. No automatic recurring job.
  • Stop on HTTP errors, including 401, 403 and 429. Persist Retry-After cooldown across restarts when supplied. No automatic retry loop.
  • Thirty-second network timeout, 20 MB response cap, fixed HTTPS API origin, no HTTP redirects carrying credentials.
  • Atomic page/manifest writes and a per-snapshot lock. Do not run multiple snapshots concurrently; pacing is per process, not shared across processes. A hard-killed process can leave a stale lock; check that no collector is running before removing it.

data/raw/faf_api/<snapshot>/ contains:

  • manifest.json: exact plan, per-resource progress, run request counts and stop reason.
  • pages/: cached raw JSON:API pages with request URL and retrieval time.
  • exports/map.json, mapVersion.json, mapVersionReview.json, game.json: primary resources deduplicated by ID.
  • exports/included_resources.json: relationship resources, including rating summaries.
  • exports/game_classifications.json: each observed game's classification and map IDs.
  • exports/summary.json: qualifying counts by map version and parent map, coverage and completeness flags.

All these files are under the repository's ignored raw-data directory. No replay binaries are fetched. The review output contains community text and reviewer relationship IDs; treat publication separately from local collection.

Meaning of counts

The rule is at least two distinct human player IDs and replayTicks >= 3000, corresponding to five simulation minutes. AI participants do not count. Missing AI flags, player identity, included participant records or tick data produce an unknown classification. No ranked-only, mod, victory-condition or opposing-team restriction is imposed.

This first implementation assumes playerStats linkage lists actual participants completely. Confirm that assumption, AI fields and spectator handling against known live games before using counts for analysis. The server duration filter means missing-tick games are not sampled; the summary cannot measure the fraction of all games missing duration.

Each resource has its own complete flag. A budget-limited sample must never be presented as total map usage. Empty collections terminate paging instead of assuming that a requested page size was honored. Overlapping pages stop the run; offset pagination and mutable metadata still cannot guarantee a transactional snapshot. Refreshes should use a new directory rather than treating cached old pages as fresh. Historical updates and deletions require later reconciliation.

The original faf_collect pilot does not match local maps. The faf_library calibration described below adds local-map matching and restricted featured-mod fields. Automatic review-summary reconciliation, broad historical backfill and exact historical rating analysis remain unimplemented.

Library calibration

faf_library uses the annotation app's 6,047-map catalog as its explicit collection scope. The separate extraction CSV has 6,053 rows; it is not the input to this run. A catalog hash is stored to prevent resuming against a changed library.

$env:PYTHONPATH = 'src'
.venv-codex/Scripts/python.exe -m supmapai.tools.faf_library --start 2026-09-29 --output data/raw/faf_api/library_calibration_20261006 --max-requests 20 --run

Omit --run to preview the plan. The directory name identifies the planned snapshot; actual capture timestamps are in the cached responses and manifest.

Within the same 20-request budget, the calibration reads the featured-mode list, one game page plus candidate totals for each of seven days, folder lookup batches of 50, and review batches for matched parent map IDs. It prioritizes the catalog's priority maps for folder lookup. Games must have featured mode faf and at least 3,000 replay ticks; distinct human participants are counted locally. Each day's sample is the first page in ascending game-ID order, not a random sample. Its qualifying fraction must not be generalized to the whole week.

The matching report distinguishes exact matches, case-normalized matches, ambiguous matches, queried-but-unmatched folders, and pending folders. Versions included in game or review results may provide additional matches before their dedicated lookup batch is reached. A match does not guarantee that its rating summary has been collected yet.

The cached calibration samples do not advance to further game pages when this command is resumed. Resume continues folder lookups and review extraction. The week-wide totals measure candidate records before the two-human filter; they are used only for an initial request-volume estimate. A full game-history collector is still a separate next stage.

Outputs under exports/ include coverage.json, library_matches.csv, library_matches.json, ratings.json, reviews.json, and game_classifications.json. Ratings preserve both version and parent summaries. Missing summaries remain null; absent counts are not confirmed zero. Review batches have individual completion state in the manifest, and the full-library review collection is not complete until all matching and review work has finished.

The historical ladder1v1 featured-mode identifier exists in the live catalog. This calibration includes only faf; establishing whether older standard ranked games use ladder1v1 remains necessary before historical backfill. Standard featured mode also does not prove absence of additional simulation mods.

Calibration results captured 2026-10-07

The initial run used its 20-request budget. Sparse field selection for only featuredMod unexpectedly omitted game and participant attributes/relationships. An explicit field list for each included resource type corrected this. A separate repair run fetched just the seven daily pages (seven requests, the same five-second pacing). Original raw pages remain available, and exports prefer the repaired page for each day without counting both.

Results from these 27 requests:

  • 500 folders queried directly in ten batches; additional versions included with game/review data brought matches to 602 of 6,047 library entries (552 exact and 50 case-normalized). Another 5,445 remain pending; pending does not mean absent from FAF.
  • 144 reviews downloaded for matched maps, including 62 with text. Review batch 0 is complete; batch 1 still has additional pages. This is not complete review coverage.
  • 700 game records sampled, one ascending-ID page per day: 383 qualifying, 310 under two humans, seven with unknown participant data.
  • FAF reported 14,366 candidate games across the week before applying the human-participant rule. Full retrieval would take 146 pages with the observed daily pagination.
  • Extrapolating this single week's candidate volume gives about 749,085 records/year, or a lower bound of 7,491 100-record page requests. Five-second spacing alone is approximately 10.4 hours; allow roughly 11 hours including responses and page rounding. This is a planning estimate for all standard FAF games, not a prediction for our library or a count of qualifying matches.
  • Median response time was about 0.14 seconds in the first run and 0.125 seconds in the repair. Neither run encountered a throttling response. Both library matching and week-wide game collection remain incomplete.

Next: finish the remaining 111 folder lookup batches and review pages in bounded runs, establish the historical standard-mode allowlist, then compare the same seven-day volume filtered to matched parent map IDs. Use that measured reduction to decide the historical collection schedule. Do not infer annual qualifying counts from the first-page samples.
