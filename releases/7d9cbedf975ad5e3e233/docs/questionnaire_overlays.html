Questionnaire PNG overlays

The questionnaire stacks ordinary HTML images. No 3D renderer or shader is needed. The vault preview stays the default background; all overlays start off. Open Map overlays below the picture to choose layers and opacity. Click the map to enlarge it; the enlarged view loads native-resolution PNGs.

Six transparent layers: passability, static spawns/resources, supported adaptive slot links, reclaim mass, reclaim energy, and props/units/wrecks. Labels and legends live in the controls, not in the PNG pixels. Dense masks appear below resource markers. Adaptive settings remain outside the MVP: links describe default options with all recorded spawn slots open, independently of the configuration selected in the questionnaire answers. Static resources show all definitions; the adaptive layer shows which are inactive.

All overlays use world x to the right and world z downward, the same full map extent, no crop or vertical flip. Reclaim retains sums per 4×4 world-unit tile; empty tiles are transparent and unknown values do not contribute. Pathing is the existing static slope/depth estimate (0.75 slope, 25 amphibious depth), not engine pathfinding. Unknown movement validity produces transparent pixels.

Some vault pictures are custom artwork, cropped, or perspective views. Their coordinate registration has not been verified. Choose Extracted terrain for guaranteed alignment between extracted layers. Rectangular maps retain their aspect ratio on that background. No claim is made that arbitrary vault artwork can be registered automatically.

The original smoke covered Adaptive Diversity, Adaptive Archsimkats Valley, Blackstar, and Paradise-Stream. Full-library assets are now generated separately in data/processed/library_overlays. The original master render collection is preserved. The viewer marks maps unavailable until their new package is ready.

From the repository root, export the entire ready questionnaire pool:

$env:PYTHONPATH='src'
.venv-codex/Scripts/python.exe -m supmapai.tools.export_questionnaire_overlays

For the entire supported library, including hidden maps:

$env:PYTHONPATH='src'
.venv-codex/Scripts/python.exe -m supmapai.tools.export_questionnaire_overlays --scope library --workers 4 --memory-budget-mib 1536 --output data/processed/library_overlays

The library selection is the 14,749 successfully decoded maps in the existing master manifest. The six already unsupported render sources are excluded from this run. No previously failed map download is retried.

Omit --map-id for the whole pool, or repeat it for a subset. This reads downloaded sources and the existing pinned blueprint/rule cache; no download retries or FAF requests occur. It re-extracts with the current decoder, including legacy water/prop fixes and map-local blueprints, rather than removing backgrounds from old annotated PNGs. The overlay-only path skips terrain component statistics, duplicate unit/prop parsing, legacy views and comparison panels. Four persistent workers reuse blueprint caches; a 1.5 GiB budget reduces simultaneous large maps. The scheduler looks ahead for smaller jobs that fit spare memory behind a large map, and reserves a solo turn for maps larger than the whole shared budget. Lossless PNG compression level 2 reduces encoding cost without changing pixels. Native and web references share one file for maps at or below 1024 pixels. The six-map benchmark found 2.24–4.17× lower extraction time, with all 42 layer images pixel-identical and reclaim totals unchanged; timings are in data/processed/overlay_benchmark/results.json.

Stalled maps are skipped after 240 seconds (--timeout). Run one exporter at a time; a PID lock prevents competing writers. progress.json updates every five seconds with ready/failed/pending counts, active maps, heartbeat and remaining time estimate. Manifests, the CSV and questionnaire lookup refresh every minute and at completion. Each finished map has its own immediate asset.json checkpoint. Resume validates native/web PNG hashes and source size/mtime; extraction/packaging, pinned-blueprint or compression changes invalidate the cache; operational scheduling changes preserve it. Failures are in failures.json, and are skipped on resume unless --retry-failed is set.

Outputs:

  • data/processed/library_overlays/<map_id>_<version_id>/: six RGBA layers and terrain base, web PNGs capped at 1024 without enlargement, plus native PNGs and an asset.json with hashes, source identities and validation.
  • data/processed/library_overlays/progress.json: active maps, completed/total, elapsed time, heartbeat, failures, and final state.
  • src/data/overlay-assets.json: compact exact-version questionnaire lookup; no basename guessing or fallback to another map version.
  • data/processed/library_overlays/manifest.json and overlay_catalog.csv: the complete library lookup, PNG paths, map/version identity, hidden/ranked flags and per-map status. Detailed numerical validation stays in each package.

The local Vite server serves /overlays from the library directory, with fallback to the original public/overlays smoke packages. The hosted build copies only PNG paths referenced by the questionnaire into dist/client; other library maps, work directories and progress logs are excluded. Set MAPGEN_OVERLAY_DIR to use a different local asset root. For an external static asset host, set VITE_OVERLAY_BASE_URL before building and upload the same overlay directory structure there separately. Rebuild after bulk export to include the updated lookup. No deployment or publication occurs during collection.

Validation: extraction test suite includes empty alpha, preserved wreck mass, energy zero transparency, inactive crosses, and RGBA resizing with rectangular aspect ratio. Browser checks cover multiple loaded layers over the actual vault image, terrain switching, opacity, and native images in the enlarged view.

After the library run completes, verify every PNG and the library-wide coverage:

$env:PYTHONPATH='src'
.venv-codex/Scripts/python.exe -m supmapai.tools.audit_overlay_library

This checks hashes, PNG CRCs, dimensions, RGBA modes, exact manifest/CSV identities and explicit failures against the original master collection, then saves audit.json.
