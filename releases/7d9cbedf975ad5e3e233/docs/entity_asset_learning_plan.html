Learned Asset Diversity And Terrain Attachment

Status: alternative proposal, superseded for the MVP. The active direction is learned physical-value heatmaps plus an asset/budget composer, starting with tree energy and natural-rock mass. See reclaim_value_heatmaps.md. Blueprint-ID and pose learning below are not prerequisites for the current experiment.

What The Current Model Does

The placement baseline predicts four conditional spatial PDFs and independently samples typed points with explicit count budgets. It does not predict blueprint IDs, joint forest/rock configurations, local pose, or instanced mesh footprints. The one-pine/one-rock appearance is a fixed visualization palette in the exporter, not a lack of variety in source maps. Random asset substitution could add visual variety but would not teach terrain relationships.

The extracted catalog contains 1,508 blueprint references: 328 tree, 358 rock, 530 wreck and 292 other references. These are references, including custom assets and different wreck mechanisms, not a claim that every entry is a portable stock prop. Existing compact metadata preserves the blueprint IDs and source provenance; the four-field PDF targets discarded that identity for the first baseline.

Data To Add Or Retain In Training Targets

For each entity retain a canonical asset ID, broad role, asset family/palette, tree-group flag, instance XYZ, orientation basis, scale, footprint and known blueprint economy values with availability masks. Resolve stock assets against actual installed archives and custom assets against their bundled files/hashes. Do not treat unknown asset values as zero or transfer custom map paths blindly. Separate singular trees, tree groups, rock families, decorative props and wreck types; budgets must state whether they count source instances or visible stems.

Current snapshots lack full per-instance orientation/scale; the .scmap reader already traverses those fields but did not retain them. Re-extract those fields for accurate pose/footprint learning. Do not overwrite the frozen historical training releases; publish a new aligned release with the same family split.

Living civilian buildings are absent from current reclaim targets by design. Use original extraction records to add a separate structure layer carrying unit blueprint, army/allegiance, orientation and live/wreck state. Natural props belong in the .scmap prop section; live civilian units/buildings belong in save-Lua army/group records. A unit blueprint must not be emitted as a rock-style prop.

Proposed Learned Model

Use a hierarchy rather than a global arbitrary asset shuffle:

  1. A map-level palette/style condition or learned palette selector chooses a coherent asset-family context. Texture/material data can supply additional context when that stage is ready.
  2. A stochastic, cluster-aware layout model learns forest patches, rock fields, cliff-edge bands and expansion reclaim regions. Derive multiscale cluster supervision from source entities; do not create fixed procedural cluster layouts at generation time. Generate full maps, then apply chosen symmetry.
  3. A local placement/asset head predicts precise offsets and family/blueprint identity given the cluster, nearby terrain and neighboring entities. This replaces the current independent within-cell jitter and coarse category-only asset binding. Footprint, scale and pose predictions follow from the richer source labels; blueprint values determine actual mass and energy.

Keep exact budget control in decoding. Do not restore an inference-time terrain validator as a way of making the learned model appear more terrain-aware.

The terrain inputs already contain height, water distance/depth and passability, but explicit multiscale slope, normals, curvature, plateau/cliff/shore distances, and resource/base proximity can make local relationships easier to learn. These are conditioning features, not hard placement masks. Exact native features and local offsets matter near narrow terrain features that a 128-grid PDF smears. Pose grounding and terrain-normal relationships are distinct from deciding where an entity belongs and should be evaluated separately.

Evaluation

Keep raw in-game exports. Measure placement likelihood against held-out targets, per-asset slope/shore/cliff-distance distributions, pairwise spacing and cluster size distributions, palette coherence and asset-type reconstruction. Count matching is a decoder guarantee, not a model quality score. Where several asset variants are equivalent, exact author-ID matching alone is not a quality measure. Use player review alongside those diagnostics.

Next implementation priority is a new asset/pose/terrain target release followed by a small cluster-aware placement plus asset-selection trial. No asset-diversity or civilian-building training run was started while making the raw export change.
