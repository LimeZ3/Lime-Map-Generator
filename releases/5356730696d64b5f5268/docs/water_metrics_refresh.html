Water coverage provenance and questionnaire repair

The questionnaire's waterPercent and buildablePercent originally came from data/audit/v1_current/dataset_audit_maps.csv. This was generated from the older data/interim/batches/*/*_terrain.csv files. Rebuilding PNG overlays did not refresh those numerical fields.

Dragons Tooth Mountains (13875_29369) demonstrates the problem:

Field Older extraction Current serialized decoder
Water source height_histogram_fallback_uncertain serialized_water_disabled
Water coverage 76.8486% 0%
Buildable area 1.9775% 78.7281%

Its old fallback guessed sea level at the most common terrain height (16). Ground equal to this level counted as water, despite the old record reporting zero water depth throughout. The actual file has water disabled. An unused stored water elevation is not evidence of an enabled water surface.

The repair reads height cells, playable bounds and serialized water settings using the current decoder, then calculates water/buildable masks with the shared terrain rules. Unknown/unsupported sources remain unavailable, not dry. It does not render images, evaluate scripts or request anything from FAF.

Run from the repository root:

$env:PYTHONPATH='src'
.venv-codex/Scripts/python.exe -m supmapai.tools.refresh_terrain_metrics
.venv-codex/Scripts/python.exe -m supmapai.tools.refresh_terrain_metrics --apply

The first command audits source files from the overlay collection plus canonical local folders and writes data/processed/terrain_metrics_current/metrics.json and report.json. Metrics retain source SHA256 hashes, water provenance, playable bounds and a full-map water percentage for comparison with PNGs. The displayed coverage uses the playable area, as the full decoder does.

The second command updates only water/buildable metrics and their provenance in the existing questionnaire catalog, preserving IDs, vault metadata and reviews. Catalog generators also apply this cache, using exact vault versions or exact canonical folders. Existing historical V1 batch/audit outputs are retained for comparison; they are not the corrected metric source for new training exports. Use this refreshed cache or rerun the current decoder for such exports.

No PNG regeneration or publication is required. A hosted website needs its normal build and deployment before these corrected numbers appear there.

Validation includes regression tests for disabled water above terrain, distinguishing unknown from dry, and exact version joins. Six real maps were compared against decode_scmap for water coverage, buildable area and water provenance: Dragons Tooth Mountains, Setons, Adaptive Diversity, Adaptive Archsimkats Valley, Lost Island 4 and Blackstar. All fields matched exactly.
